# v0.1 API review: fixes and breaking changes before the first tag

Date: 2026-09-13
Status: approved by the user ("おk、一気に進めて"); the two open questions were decided by the user (V1, V2), the rest follows the reviewed recommendations
Follows: [2026-09-13-layered-api-design.md](2026-09-13-layered-api-design.md), [2026-09-13-access-tokens-design.md](2026-09-13-access-tokens-design.md)

## Problem

grantor is about to get its first tag, v0.1.0. Once tagged, the module proxy keeps the version forever and users build on its API. An independent review of the public API found:

- **Unsafe defaults in the API shape.** A nil list means "all" and an empty list means "none" (`TokenRequest.Scopes`, `Approval.Audience`, `Grant.Audience`). The usual Go filter idiom produces nil when it removes everything, so removing every scope or audience grants all of them. `Approval.Scopes` already uses the opposite convention.
- **A remaining grant-destroying failure.** Tokens are stored after the authorization code or refresh token is consumed. If storing fails, the client's retry is treated as reuse and the grant is revoked.
- **Operational errors reported as 404.** Every `IssuerFor` error, including a tenant database outage or an issuer without valid keys, becomes `404 Not Found`, logged at debug level.
- **Mutable global errors.** `ErrAccessDenied` and friends are exported `*Error` pointers; changing a field changes a global and races.
- **An awkward custom grant API.** `GrantFunc` must capture the provider to call `IssueTokens`, cannot tell which issuer it runs for, and `IssueTokens` is public although only valid inside a grant.
- **A storage contract that cannot grow.** Adding a method to `Storage` breaks every implementation, `ClaimAssertionID` only fits client assertions, and `RevokeGrant` requires remembering revoked grants forever.
- Naming, documentation and release gaps: `TokenType` clashes with `token_type`, secret helpers are ambiguous, no runnable examples, the conformance suite only runs locally, no changelog.

## Goal and success criteria

1. Every list that selects scopes or audiences treats nil and empty the same: nothing. Removing everything never grants more.
2. No failure while issuing tokens (hook, encoder, claims, signing or storage) consumes an authorization code or refresh token.
3. Custom grants return what they grant; grantor issues the tokens.
4. Future features (PAR, DPoP, JAR, logout sessions, device grant, dynamic registration, cleanup) can be added without adding methods to `Storage`.
5. Applications can tell an unknown issuer from an operational failure, invalid approvals from outages, and get the HTTP status of an `*Error`.
6. pkg.go.dev shows runnable examples for the main extension points; README, design notes and a changelog describe v0.1.0.
7. The OpenID conformance plans run in CI on every push and pull request.

All existing guarantees hold, `go test -race` passes in both modules, and the conformance plans keep passing.

Out of scope: discovery metadata hooks, metrics or tracing events, `Config.Now`, issuer caching, response extension parameters for custom grants, new protocol features. The v0.1.0 tag itself is created only after the user confirms.

## Decisions

| # | Decision | Rationale |
|---|---|---|
| V1 | Nil and empty lists mean "none" for `Approval.Audience`, `Grant.Audience` and `Issuance` lists. Defaults are prefilled instead: `AuthorizationRequest.Audience` starts as `Client.Audience`. `TokenRequest.Scopes` becomes read-only; scope narrowing at the token endpoint moves to `BeforeIssue`, which gains `Issuance.Request`. *(User decision.)* | Fail-safe: forgetting or filtering to nothing narrows. Matches `Approval.Scopes`. Request-dependent narrowing stays possible through `Issuance.Request`. |
| V2 | `GrantFunc` returns `(*Grant, error)`; `Provider.IssueTokens` is removed; `TokenRequest` gains `Issuer` and `HTTPRequest`. *(User decision.)* | Grants decide access, grantor issues. No provider capture, no misuse outside a grant, issuer-aware grants, request headers available. |
| V3 | Issuance order is plan → mint → store → consume. When consuming fails, the stored tokens are revoked one by one (best effort). | A stored but undelivered token is harmless; a consumed code without delivered tokens destroys the grant on retry. Every race ends with the new tokens either delivered or revoked. |
| V4 | `RevokeGrant` no longer covers tokens created after the call. | With V3 no token of a grant can be stored after the revocation that should cover it, so storage no longer keeps revoked-grant markers forever and every record can expire. |
| V5 | `ClaimAssertionID(ctx, issuer, clientID, jti, expiresAt)` becomes `ClaimOnce(ctx, key, expiresAt)`. grantor builds keys as a kind prefix plus a hash, e.g. `client-assertion:` + base64url(SHA-256(issuer, client ID, jti)). | One primitive for client assertions now and DPoP proofs or request objects later. |
| V6 | `Storage` never gains methods. Future features that need storage get their own small interface in an optional `Config` field (nil disables the feature). Records may gain fields; implementations must persist every exported field. `storagetest` fails when its fixtures leave an exported field at its zero value. | Evolvability without type assertions; new fields are always round-trip tested. |
| V7 | `IssuerFor` errors that wrap `ErrNotFound` produce 404; other errors, a nil issuer, and issuers that fail validation produce 500 (`server_error` on JSON endpoints) and are logged at error level. | Outages and misconfiguration must be visible and must not look like unknown tenants. |
| V8 | The exported `*Error` variables are removed. `Deny` takes `*Error` values built by the caller; nil still means `access_denied`. `(*Error).Is` keeps comparing codes. | No mutable globals. |
| V9 | `Approve` wraps approval validation failures in `ErrInvalidApproval`; `Approve` and `Deny` wrap invalid request edits in `ErrInvalidAuthorizationRequest`. They return nil once they have written a response, including an error response for a storage failure. | Applications tell their own bugs from outages without double-writing responses. |
| V10 | `(*Error).HTTPStatus() int` is exported. | Custom error pages and token endpoints choose the same status grantor would. |
| V11 | `Approve` rejects an empty audience when the client's configured access token format (client, then config) is `jwt`. | Surfaces the mistake at the approval instead of a failed code exchange later. |
| V12 | Renames: `TokenType` → `TokenKind` (`Token.Type` → `Token.Kind`, JSON `kind`; constants `TokenKind…`), `GenerateSecret` → `GenerateClientSecret`, `HashSecret` → `HashClientSecret`, `PathOpenIDConfig` → `PathOpenIDConfiguration`, and a new `PathAuthorizationServerMetadata`. | `token_type` is a protocol term (Bearer, DPoP, RFC 8693 types); explicit secret helpers; both discovery paths exported. `…SigningAlg` client fields keep their names, which mirror registration metadata. |
| V13 | Documentation promises: endpoints of features that are not configured are never served; `Client.SecretHash` is an opaque verifier produced by `HashClientSecret` and only suitable for generated secrets; `Config` maps must not be modified after `New`; `Token.Hash` is base64url without padding; which `Issuance` fields the hook may change. | Future-proof contracts without code. |
| V14 | Conformance CI: a GitHub Actions workflow runs `examples/conformance/run.sh` on pushes to main, pull requests and manual dispatch, with the suite pinned to a release and `host.docker.internal` mapped to the host gateway. | Criterion 7; pinned for reproducibility; the mapping makes the Docker Desktop setup work on Linux runners. |

## API changes

### Lists and requests

```go
type AuthorizationRequest struct {
	// ...
	// Audience is the audience the request may be approved for. It starts as
	// Client.Audience.
	Audience []string `json:"audience,omitempty"`
}

type Approval struct {
	// ...
	// Audience is the granted audience, a subset of the request's Audience.
	// Nil or empty grants no audience.
	Audience []string
}

type Grant struct {
	// ...
	// Audience must be a subset of Client.Audience; nil or empty grants no
	// audience. Other audiences fail with invalid_target.
	Audience []string
}

type TokenRequest struct {
	Client    *Client
	GrantType GrantType
	// Scopes is the scope parameter, or nil if it was not sent. Changing it
	// has no effect; narrow scopes in Config.BeforeIssue.
	Scopes []string
	Form   url.Values
	// Issuer is the issuer URL the request was sent to.
	Issuer string
	// HTTPRequest is the request passed to ParseTokenRequest. Its body has
	// been read.
	HTTPRequest *http.Request
	// unexported: iss, client copy, scopes copy
}

type Issuance struct {
	// ...
	// Request is the token request the tokens are issued for. Changing it has
	// no effect.
	Request *TokenRequest
}
```

Approval validation: `Approval.Audience` must be a subset of the request's audience and of the current `Client.Audience`. For a saved request the stored copy's audience applies (a differing `Audience` is `ErrAuthorizationRequestModified`, like other protocol fields); for an unsaved request the passed `Audience` must itself be a subset of `Client.Audience` (otherwise `ErrInvalidAuthorizationRequest`).

Token endpoint: `Exchange` narrows with the scope parameter captured by `ParseTokenRequest`, not with `TokenRequest.Scopes`. The client credentials grant keeps issuing `Client.Audience`.

### Custom grants

```go
// GrantFunc handles a custom grant type at the token endpoint and returns
// the access it grants; grantor issues the tokens. Returning an *Error sends
// it to the client; other errors become server_error. Returning nil and no
// error is a server error.
type GrantFunc func(ctx context.Context, req *TokenRequest) (*Grant, error)
```

`Provider.IssueTokens` is removed. The checks it made (subject syntax, scopes within the client, `openid` and `offline_access` need a subject, refresh tokens need the refresh grant, audience within the client) apply to the returned `Grant`.

### Issuance and storage

```go
type Storage interface {
	// ...unchanged methods...

	// RevokeGrant revokes every token that has the given GrantID. Revoking an
	// unknown grant is not an error.
	RevokeGrant(ctx context.Context, grantID string) error

	// ClaimOnce records key until expiresAt. It returns ErrConflict if key was
	// already claimed and has not expired. Keys are ASCII strings of at most
	// 128 bytes. The operation must be atomic: when called concurrently for
	// the same key, exactly one call succeeds.
	ClaimOnce(ctx context.Context, key string, expiresAt time.Time) error
}
```

The `Storage` doc states the evolution policy (V6). Code exchange and refresh: `planIssuance` → `mintTokens` → `storeTokens` → `consume`; on a consume error the stored access and refresh tokens are revoked with `RevokeToken`, errors ignored and logged.

### Issuers and errors

`Config.IssuerFor` documents the error mapping (V7). `withIssuer`, `ParseAuthorizationRequest`, `ParseTokenRequest`, `AuthorizationRequest`, `Approve`, `Deny` and `ValidateAccessToken` share one classification.

```go
var (
	ErrInvalidApproval             = errors.New("grantor: invalid approval")
	ErrInvalidAuthorizationRequest = errors.New("grantor: invalid authorization request")
)

// HTTPStatus returns the status grantor uses when it writes e as a JSON error
// response: StatusCode if it is a 4xx or 5xx status, otherwise the status
// for Code.
func (e *Error) HTTPStatus() int
```

## Documentation, examples and release

- `example_test.go` (package `grantor_test`): `ExampleNew` (runnable, prints the discovered issuer), `Example_multipleIssuers`, `ExampleProvider_ParseAuthorizationRequest` (custom authorization endpoint), `ExampleProvider_Exchange` (custom token endpoint), `ExampleConfig_beforeIssue`, `ExampleGrantFunc`, `ExampleAccessTokenEncoder`; `storagetest/example_test.go`: `ExampleRun`.
- Doc fixes: `Issuer.Keys` and `SigningKey` sign ID tokens and JWT access tokens; `Token.Hash` encoding; `Approve` return contract; `Config` maps immutable after `New`; `SecretHash` contract; unconfigured endpoints never served.
- README, `docs/design.md`, `doc.go` and all examples follow the new API.
- `CHANGELOG.md` in Keep a Changelog format with a `0.1.0` entry.
- `.github/workflows/conformance.yml`; `run.sh` reads `CONFORMANCE_SUITE_REF` (git tag) and uses the matching image tag, and applies `examples/conformance/compose-host.yml` (`extra_hosts: host.docker.internal:host-gateway` on the suite server). Results are uploaded as an artifact.

## Testing

- Nil/empty: approval with nil or empty audience grants none; filtering `Issuance.Scopes` or `Issuance.Audience` to nil grants none; changing `TokenRequest.Scopes` has no effect; `Issuance.Request` exposes form values; unsaved request with widened `Audience` fails with `ErrInvalidAuthorizationRequest`; JWT client approval without audience fails with `ErrInvalidApproval`.
- Custom grants: returned grants are issued; nil grant is `server_error`; `*Error` passes through; subject, scope, refresh and audience checks; `TokenRequest.Issuer` and `HTTPRequest` are set.
- Storage ordering: `CreateToken` failing once during code exchange and during refresh leaves the code or refresh token usable; a failed consume revokes the stored tokens.
- `storagetest`: `ClaimOnce` (conflict, expiry, concurrency); fixture completeness check; the "RevokeGrant covers later tokens" case is removed.
- Issuers: `IssuerFor` returning `ErrNotFound` → 404; other error → 500 and an error log; issuer with invalid keys → 500; same mapping for token endpoint JSON errors.
- Errors: `HTTPStatus`; `ErrInvalidApproval` and `ErrInvalidAuthorizationRequest` via `errors.Is`.
- Examples compile and runnable examples pass; existing tests updated to the new names; e2e and low-level example tests pass; conformance plans pass locally and in CI.
